# S6.3 R2 producer verification evidence

This is the producer package for `ANDIRIT-CI1A-S2.6-WP-S63-IMPL-01-R2`. It is separate from the independent Q1 evidence and the historical R1 extension. See the formal report and findings matrix for the producer disposition and limits.

- `receipts.zip` preserves the detached Windows campaign, original and remediated Q1 harness replays, successful and expected-failed local commands and TRX, GitHub run/job metadata, raw decoded job logs, and downloaded hosted test and Cobertura coverage files. `results-summary.txt` records suite totals, coverage numerators and denominators, and each verified named outcome.
- `campaign-r2.py` takes the fresh detached tested worktree, the existing Q1 checkout, and a new output directory. Run it with Python from an environment with `dotnet`, `pwsh`, and `git`. The first build is per-project. It compares worker DLL, dependency and runtime configuration hashes, parks the original worker build output, runs three copied-worker cases and twenty dedicated D-07 repetitions, and runs external missing- and early-worker controls before restoring the copies. The early worker forwards only the setup publish and exits 19 before READY in the hold phase. The exact Q1 harness is built again against R2, with its original late-success assertion intentionally unchanged.
- `check-verifier.py <verify-s63-results.ps1> <downloaded-or-local-test-results> <tested-sha>` checks the positive and malformed-evidence controls. The verifier in the tested commit requires one test result file from each project, binds hashes to the checkout and platform receipt, verifies P-01 through P-16 and the supplemental D-05/D-07 cases, and checks the required worker and queued-reader observations.
- `collect-hosted.ps1` queries the exact hosted run and downloads its artifacts and job logs from GitHub. `summarize-r2.py <receipts-directory> <tested-sha> <run-id>` independently correlates the downloaded XML results and coverage with the GitHub run/job metadata and recomputes the per-case summaries.
- `seal-r2.py verify <repo> <sealing-commit> <repo-relative-package-directory>` verifies a package from the committed Git objects, including the exact path set, original payload Git tree, sealed Git bytes and package SHA-256. The manifest excludes its own bytes. Use this command for both this package and the R1 erratum.

To check an extracted hosted Ubuntu artifact again, run the tested revision's `verify-s63-results.ps1 -Results <directory> -ExpectedSha <tested-sha> -ExpectedRunId <run-id> -ExpectedRunAttempt <attempt> -ExpectedRunnerOS Linux -ExpectedRunnerArch X64`. Source the expected revision and run from GitHub run/job metadata. The named mapping is explicit in that script. P-12's managed serialization observation and P-15's native ownership and reopened same-repository publication are distinct D4-10 observations. D-05 supplements ownership with inherited cancellation and durable reopen. D-07 supplements recovery. P-04/P-08 and E/F provide distinct failure, reopen and rebuild observations.

Windows campaign times are the host's recorded clock times. Native error objects in the deadline regressions are obtained from LatticeDbSharp and are paired with controlled clock progression and instrumented disposable handles. A native call already in progress can return after the acceptance deadline. The control logic disposes the late handle and rejects the result. Probe I and the repeated D-07 executions separately describe actual worker termination and reopen.
