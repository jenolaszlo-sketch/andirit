# Reproduce QUAL-02

Use Windows x64, the SDK and runtime from `gates/toolchain.log`, and the pinned NuGet libraries, including LatticeDbSharp 0.2.0. All native stores are disposable. The commands below assume a new scratch directory writable by the reviewer. Keep its path short enough for Windows build tools. The two exported directories are plain Git archives with no Git metadata.

1. Copy `export.py` to the scratch directory and run it. It reads `D:/projects/Andirit/.git` and creates `baseline` and `corrected` at the qualified revisions. Verify trees and provenance using `preflight.log` and `verify-integrity.py`.
2. Copy the files from `harness/binding` to scratch `probe`, and from `harness/controls` to scratch `control`. Copy the run scripts to scratch `evidence`. Each script writes its own log and JSON receipts and accepts `-Work <scratch-directory>`. The fixture comes from the preserved QUAL-01 package in the corrected export. The initial binding harness was derived with `prepare-probe.py`. The copied harnesses are the maintained reproduction sources.
3. Run `run-gates.ps1` with `-Root <scratch>/corrected -Evidence <scratch>/evidence/gates`. Create the gates directory before running it. Use `NUGET_PACKAGES` set to the local vetted package cache if needed. The tests, format command and generated oracle output are compared in `check-results.py`.
4. Run `run-probes.ps1`, `run-additional.ps1` and `run-state.ps1` in their default profiles. Run `run-state.ps1 -Retry` to exercise structured conflict refusal and the publication and target continuation negatives, along with constructed partial storage. Run `run-additional.ps1 -Baseline` for baseline finding comparisons and `run-additional.ps1 -Declared` and `-Declared -Baseline` for the exactly-one-missing-declared-unit fixture. Fresh-process phases must keep the same executable and database paths within one profile.
5. Run `run-confirmation.ps1` and `retry-confirmation.ps1` for inherited authentic-copy and P2 replay. The initial script records two explained attempts. The retry arranges the untampered P2 reopen first and opens only a verified disposable graph-only copy. Use the coverage log and Cobertura output to verify the gate's exit and measured denominator.
6. Run `python check-results.py <scratch>/corrected/docs/reviews/CI1A-S2.5-WP-S25-4-QUAL-01-evidence/fixture` from the scratch evidence folder. The separate Python implementation hashes the contract tuples from the source and recorded descriptor primitives and compares native facts and TRX identities. Run `python check-findings.py` and `python reconcile.py <canonical QUAL-01 evidence directory>` to recompute the finding summary and row counts.

Fresh Windows executions reuse the source scaffolding candidly identified in the report. The classification and identity oracles, added variants and cross-checks are reviewer-controlled. The constructor/property/method-group assertions intentionally retain the approved oracle and exit 1 when the matrix behavior fails. The known fault and unknown-outcome cases use managed injection rather than process or power failure. Historical database masters are only read, hashed and copied.

The manifest contains SHA-256 and lengths over exact package bytes and excludes itself. The Git commit binds the package and report. Run `python seal.py --verify <evidence-dir>` to independently verify membership and hashes at the sealed checkout.
