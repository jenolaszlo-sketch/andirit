## Independent oracle and matched comparisons

1. **Freeze sources and scope before observing the candidate.** Record original commit and Git blob for each file, staged bytes and SHA-256, logical relative path, expected project membership, framework references, parse/compilation options and the change sequence. Copy from Git blobs where checkout filters could rewrite bytes. Use explicit paths with ordinal ordering. Check the complete project closure and source binding before positive cases run. Pin any additional fixture's declared source and producer provenance.
2. **Freeze fixture-derived ledgers.** A reviewer identifies project/file/symbol declarations and relationships from source and direct Roslyn binding. For every selected site, record its path, span, owning unit, owner and resolved target, overload signature, kind, and expected first evidence for an aggregate edge. Independently implement the established legacy identifier recipes where required, or recover exact identities from an independently pinned and authenticated legacy writer for the identical source and contract. Include full node/edge identity sets and expected counts by kind and relation, both native endpoint identities and contributor multisets, and exact API sequences from a small independent traversal of the frozen adjacency. Confirm the legacy evidence/limits policy, stops and negative roots. Use the frozen F12 Roslyn oracle for supported occurrence identities/semantics. A host-scoped ID requires exact equality within the same bound inputs, and validated span/component comparisons across hosts when the contract permits host-scoped differences. Do not derive expected outcomes from the candidate's extractor, comparer, graph projection or mirror.
3. **Cross-check the oracle.** Replay the source-compatible legacy reader or graph-only writer for covered fixtures, with exact commit, input hashes and dependency resolution. SQ-04 records the original `31c33a934aa13e373d9a3a6ffbc54d789eef092c` writer and expected behavior of a historical graph-only store. Only use that binary fixture for its original inputs. Where no compatible historical writer has matching inputs, use the source-derived ledger with independently reviewed identity and traversal derivations. Freeze the oracle and let the reviewer inspect expected deltas before revealing the candidate results. Treat disagreements as an oracle/candidate investigation, preserving both artifacts. Updating a golden requires a documented, independently checked correction.
4. **Run two matched lanes on isolated stores.** Run fresh graph-only and full occurrence-enabled publication with the same repository identity, source bytes and lifecycle at each checkpoint. Include a same-store graph-only→occurrence-enabled transition for the initial event. Hold the managed-only/mirror-enabled option fixed across matched comparisons, and use a separate transition control for F-S64E-02. Compare each lane to the independent ledger, then compare the lanes. Separate deterministic graph/query observations from intentionally changed generation tokens and host-bound metadata, while retaining and asserting publication binding and expected contributor changes in their own fields. Compare before/after the same accepted source state, and compare against the independently predicted graph delta when source or project membership changes.
5. **Prove actual route and durable state.** For each qualifying native case require mirror-enabled health, an eligible direct unfiltered traversal and raw native access after writer disposal. Decode `HetuMirror` and enumerate `HetuGraphNode` and all raw incident edges independently. Compare physical counts before deduplication, prove a bidirectional relation between manifest and rows, validate endpoint/payload kinds and IDs, and show no occurrence fact in graph labels, payloads or adjacency. Count physical rows on a dedicated single-repository database so unmanifested rows cannot be attributed away. Engine-assigned numeric IDs may change across rebuilds. Their mapping and multiplicity must be exact at each checkpoint. Keep result lists in observed order and canonicalize only unordered maps and sets.
