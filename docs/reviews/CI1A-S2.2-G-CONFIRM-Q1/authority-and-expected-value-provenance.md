## 2. Frozen tuple authority (`usage4` / `asmctx3` / `compctx1`)

Encoding: domain-separated SHA-256 over UTF-8 values, each value prefixed with a
big-endian 32-bit byte length; lowercase hex; `asmctx3` carries the
`asmctx3:sha256:` prefix, `usage4` does not.

```
usage4 = SHA256("usage4", repository, plugin, "usage4-b2c-exp-r2-20261101",
                semanticUnit, path, sourceHash, startLine, startColumn,
                endLine, endColumn, targetDocumentId, asmctx3, "method-invocation")

asmctx3 = "asmctx3:sha256:" + SHA256("asmctx3-context",
                "compctx1", compctx1, metadataIdentity, moduleName,
                identifierDigest, declarationDigest, shapeDigest)

compctx1 = "compctx1:sha256:" + SHA256("compctx1-context",
                "compctx1", repositoryId, projectUnitId, assemblyName,
                metadataIdentity, moduleName, optionsDigest, sources..., references...)
```

## 4. Reference-profile identities (row 5)

| Profile | Reference identity rule | Expected result |
| --- | --- | --- |
| Production capture | `file|<actual normalized path>|<lowercase byte hash>`; host TPA inventory, distinct + case-insensitive sort, 128 MiB bound | Algorithm fidelity over equal complete inputs; **no** promise of a fixture digest |
| Frozen corpus fixture | exactly three `file|runtime/System.Runtime.dll|…`, `…/System.Private.CoreLib.dll|…`, `…/Microsoft.CSharp.dll|…` over accepted runtime bytes | Exact frozen `Leaf`/`Core` anchors |
| Comparison-only alignment | Replace only the three PE labels inside the reviewer comparison; all bytes/inputs fixed | Recovers the frozen anchors; **test-only, never production** |

The R2 project-reference item is
`compilation|<assembly>|<metadata>|<trees>` reconstructed from the verified live
dependency: trees sorted by **raw** `FilePath` (ordinal) before separator
normalization, each `Normalize(path) + "=" + SHA-256(UTF8(treeText))`, comma
joined, no dedup. Own-source identities use exact captured raw bytes (or the
oracle's per-file bytes); the dependency tree hash deliberately omits the child's
options/preprocessor/transitive context — which is why the legacy item is not a
strong reference claim and `compctx2` carries that.

## 5. Source and scope identities

- **Source identities:** exact captured raw-byte SHA-256 for own sources;
  decoded-tree UTF-8 SHA-256 for R2 dependency tree items. The two forms differ
  deliberately and are not conflated.
- **Scope identity:** `analysisscope1` = declared repository + project-unit/path
  boundary. It is **not** a source-inventory digest (A-02); membership and
  completeness come from `compilation-universe1` and each `compctx2` descriptor.
- **Provenance identity:** `compctx2` = `compctx2-context` over the same R2 fields
  with `compilation-context|<dependency compctx2>` reference items, bound to the
  live `CompilationReference.Compilation`.
