### D.4 — Index maintenance, publication and cancellation: **D4 ACCEPTED WITH EXPLICIT INVARIANTS**

Select a bounded, publication-consistent occurrence-index model. The
independently verified R2/Q3 index-freshness behaviour forms the experimental
basis.

**Required invariants:**

1. A query may use only an index consistent with the accepted published
   occurrence-fact generation.
2. A stale, unbound or unverifiable derived index must refuse with an explicit
   status.
3. A stale index must not silently trigger an unbounded full-store scan.
4. Failed staging must preserve the last accepted publication and corresponding
   valid index state.
5. Cancelled staging must not expose partial facts or index entries.
6. Superseded publication must not replace a newer accepted generation.
7. Rebuild/reopen must produce a semantically equivalent published index.
8. Contributor changes and scoped deletion must update publication and index
   visibility consistently.
9. Bounded queries must have deterministic ordering and explicit result limits.
10. Query behaviour during concurrent publication must follow a defined snapshot
    or freshness contract.

**Maintenance policy (preferred simple model):**

- Build or update the index within the accepted publication lifecycle.
- Make the index valid only when its publication identity is corroborated.
- Refuse stale or inconsistent state.
- Permit explicit bounded reconstruction where necessary.
- Verify reconstructed state before allowing normal queries.

Do **not** introduce a general background maintenance service, a distributed
index coordinator, or an automatic repair framework without demonstrated need. Do
**not** invent additional concurrency guarantees beyond Q3's evidence.

**D4 implementation qualification:** CI-1A must reproduce the applicable
stale-index, cancellation, failed-publication, supersession and reopen tests
**using actual production storage and APIs**. The previous in-process experiment
does not establish native or cross-process atomicity; record those limits
explicitly.

/// <summary>Durable embedded Andirit store backed by LatticeDB.</summary>
/// <remarks>
/// <para>
/// LatticeDB is the durable command log; all graph semantics and query behavior
/// are served from a materialized <see cref="InMemoryCodeGraphStore"/> rebuilt by
/// replaying that log on open. When <see cref="LatticeDb.LatticeDbStoreOptions.UseNativeTraversal"/>
/// is enabled, an experimental native mirror additionally serves
/// <c>TraverseAsync</c> without evidence filters from real graph structure;
/// everything else keeps delegating to the inner store.
/// </para>
/// <para>
/// Ownership and errors: a database file has a single owner process while open.
/// Opening a second store on the same path (in- or out-of-process) fails rather
/// than queuing. Native failures surface as <see cref="Andirit.CodeGraphStoreException"/>
/// with the engine error preserved as the inner exception; Andirit validation
/// failures keep their <see cref="Andirit.CodeGraphBatchRejectedException"/> contract.
/// </para>
/// <para>
/// Schema evolution: <see cref="CurrentSchemaVersion"/> is validated on open and
/// mismatches are rejected; see the repository ROADMAP for the migration policy
/// (export/import; no in-place upgrades in preview).
/// </para>
/// <para>
/// Cancellation contract: a cancellation request is honoured while an operation
/// waits for the managed write gate and immediately before the native write
/// transaction opens. It is <b>not</b> honoured inside the native transaction:
/// the pinned native dependency exposes no cancellation or interruption entry
/// point, so a cancellation that arrives during active native execution is not
/// observed, the transaction commits atomically, and the operation completes.
/// A cancelled operation therefore never exposes partial facts or index
/// entries, and a durable mutation is never reported as cancelled.
/// </para>
/// <para>
/// Cancellation outcomes are truthful and limited to three: the operation was
/// cancelled before native invocation (an
/// <see cref="OperationCanceledException"/> is thrown and no native write
/// occurred); the operation completed; or the commit outcome is unknown
/// (<see cref="CodeGraphCommitOutcomeUnknownException"/>, after which the
/// instance refuses current-state claims until the durable state is
/// corroborated by reopening the store). A managed timeout, an abandoned task
/// or a disposed caller is <b>not</b> a native cancellation and must never be
/// reported as one: callers must await the operation to learn its outcome.
/// </para>
/// <para>
/// Durability contract: the <see cref="LatticeTransaction.Commit"/> operation is
/// the durability point. After a successful commit, the outcome must not be
/// negated by a subsequent cancellation or crash; the store already refuses to
/// guess (<see cref="CodeGraphCommitOutcomeUnknownException"/>, quarantine,
/// and reopen corroboration). A cancellation or crash <b>before</b> the commit
/// leaves the previous publication and index state intact.
/// </para>
/// <para>
/// Crash, power-loss, abrupt-kill, and multi-process durability is <b>not yet
/// qualified.</b> The managed fault injector is not crash/power-loss/abrupt-kill
/// multi-process durability (DF-4/Q2-F12). The qualification must establish
/// real durability evidence — not managed fault injection — which requires new
/// instrumentation and safety scoping. The absence of a dedicated
/// crash-recovery API does not itself require an API change; ordinary database
/// reopen and recovery behaviour is evaluated first.
/// </para>
/// <para>
/// The store <b>waits</b> for an in-flight native write on disposal
/// (<see cref="IDisposable.Dispose"/> takes the same write gate); it never
/// aborts native work mid-transaction.
/// </para>
/// <para>
/// The <b>unknown-outcome path</b> covers failed commits:
/// <see cref="CodeGraphCommitOutcomeUnknownException"/>, quarantine, and reopen
/// corroboration.
/// </para>
/// <para>
/// <b>Multi-process concurrent access</b> is prevented by file locking; the
/// first writer holds the lock; others fail or wait. The durable state is
/// consistent.
/// </para>
/// <para>
/// A managed timeout, an abandoned task, a disposed caller, or a crashed
/// process is <b>not</b> a native cancellation and must never be reported as
/// one: callers must await the operation to learn its outcome.
/// </para>
/// </remarks>
