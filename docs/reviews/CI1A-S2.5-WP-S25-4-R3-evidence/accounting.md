# Q03-F-01 accounting design and trace

At R2, `PrepareAnalysisAsync` builds a declared scope and exact verified compilation universe. `VerifiedCSharpOccurrenceExtractor.Extract` examines one source compilation, counts and mints its own sites, and puts the full-universe membership and the source's diagnostics into the authority envelope. The full counts are required to validate the envelope against current live authority.

`Session.PublishOccurrencesAsync` passed the same coverage into `CodeGraphBatch`. The sink moved those counts into a replacement for each project. `InMemoryCodeGraphStore.RepositoryCoverage` merged the durable-owner contributions by addition. `LatticeCodeGraphStore.PersistOccurrences` wrote those rows and computed native publication metadata; its reopen path restored and added the same held counts. Two 2/2 rows yielded 4/4 and three 3/3 rows yielded 9/9. Zero facts still produced valid complete rows and showed the same duplication.

The producer design was stated before implementation. For complete production C# scopes, each project path maps to one source-owner row. That row contributes one declared and one verified member. The complete universe supplies exactly one such row per project, so the inputs to `Merge` are pairwise disjoint. Summation gives N/N for N projects and adds each diagnostic and occurrence count once, including when a project contains no occurrences. The R2 partial path already contributes one verified member per row and allocates all missing declarations to the first verified contribution. It gives (N + missing)/N with the same addition operation.

The envelope retains every original field and the full counts. Validation compares the entire stored row with either the matching legacy coverage or the exact source-row projection, including scope, universe, state and diagnostic counters. The projected comparison is restricted to complete coverage with the source ID matching the publication owner. Then the same live verification checks the full counts in the envelope, the exact member sequence and contexts, origin, fact payload, defining identities, and verified source. Schema, identities, `Merge`, publication order and write transaction are unchanged.

On native reopen the legacy owner row keeps its original raw coverage and authority. Its aggregation view projects the single source membership before addition and the query gate still validates the raw row. A full R2 production database opened under R3 in this environment returned `StalePublication` because platform capture includes the changed application assemblies and their hashes. The retryable qualification question is matching authority, which the controlled native fixture addresses through the existing internal handoff with fixed real platform evidence. The fixture stages all six real compilation rows with legacy 6/6 counters and verifies 6/6 on reopen. Its role is compatibility evidence. Separate production tests cover the real plugin and sink.

Production files are `CSharpCodeGraphPlugin.Session.cs`, `VerifiedCSharpOccurrenceAuthority.cs`, `CodeOccurrenceAuthority.cs` and `LatticeCodeGraphStore.cs`. Focused tests extend `S23PublicationIntegrationTests.cs`. The existing disjoint merge and authority suites exercise the unchanged semantics.
