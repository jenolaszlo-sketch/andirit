# Reproduce the R3 producer receipts

Use Windows x64 SDK 10.0.401/runtime 10.0.12 and a cached LatticeDbSharp 0.2.0. Use an empty scratch root, plain exports and disposable stores. `probes/baseline`, `probes/corrected`, `membership-tests`, `gates`, and `gates-final` preserve the observed commands, outputs and exits. `gates-final` is the final test inventory and exact-byte formatter receipt. The scratch checkout had the same production/test edits applied with the Windows conversion profile. [Compiler provenance](compiler-provenance.log) · [Toolchain](gates-final/toolchain.log)

1. Export R2 with `git -c core.autocrlf=false archive --format=zip --output=<scratch>/r2.zip 25bc6e3b4305c7ce088deb36cfb000138dc76648`. Extract to `<scratch>/production`, then copy `verify_r2_archive.py` to scratch root and run it from the repository. The verifier checks every export file against the Git blob before any R3 edits. Copy the sealed QUAL-03 `harness/corrected` to `<scratch>/probe`. Build `Qual.csproj` Release with `-p:RepoRoot=<scratch>/production -p:NuGetAudit=false`. Set `S254_QUAL02_PROFILE=corrected`. Run the five paired commands in `probes/baseline`. The harness phase `corrected` is the R2 baseline profile from QUAL-03. `m54-direct` is reused solely as the membership three-project positive control.
2. Export the R3 implementation SHA `8b83e0558f4c757272cd60a1c81b8dbc6fd7873f` with conversion disabled to a fresh `production` directory. Start with a fresh `evidence` output directory. Put `run-probes.ps1` and `run-membership.ps1` at scratch root and run from native Windows. Give the probe script the baseline copies at its designated scratch paths. It preserves the three observed stale cross-binary attempts that returned process exit 1. The standalone matching-authority legacy scenario is in `run-membership.ps1`. `run-probes.ps1` continues through B6/B7 and D3/D4/D5 after recording those exits. The restored test fixture uses the actual C# plugin/sink path, with distinct publish and verify invocations for each generation.
3. Run sealed QUAL-03 `run-gates.ps1 -Root <scratch>/production -Evidence <scratch>/evidence/gates-final`. Rerun solution discovery with `dotnet test Andirit.slnx -c Release --no-build --list-tests -m:1` for a serialized inventory. After exporting the checkout profile using `git -c core.autocrlf=true archive` at the implementation SHA, restore there and run `dotnet format Andirit.slnx --no-restore --verify-no-changes`. Preserve both formatter exits. [Formatting](formatting.md)
4. Copy `m54-probe` to a scratch build directory, build `Probe.csproj` Release with the same `RepoRoot`/NuGet arguments, and run the resulting `Andirit.CSharp.Tests.dll` once. Redirect stdout, stderr and exit separately. The executable stops if an eligible candidate has the exact outcome. [Plan](m54-plan.md) · [Observed outcomes](m54-results.json)
5. Build the supplemental disjoint native control from a scratch copy of `disjoint-probe/Disjoint.csproj` with the same arguments. Run `Disjoint.dll publish <new-db>` and `Disjoint.dll reopen <same-db>` in separate processes. This uses explicit disjoint coverage contributions to test the legacy addition contract outside the C# verified-authority path.
6. Run `verify-results.py` and `verify-b3.py` with the sealed QUAL-03 evidence directory as their positional argument. They compare independently derived fixture inventories, native rows, counters, separate PIDs, the 917-case floor, exact frozen oracle bytes and the B3 identities within each host profile. Run them in a scratch copy of the package because they write derived receipts.
7. `manifest.json` binds every package file except itself. Use source bytes from Git or an export with `core.autocrlf=false` to avoid manifest mismatch from checkout conversion. `repository.py` records the production and evidence staging allowlists, independent history verification and post-commit checks. The committed evidence is byte-identical to the sealed producer package. The final commit's own identity and verification receipt are external to that commit.
