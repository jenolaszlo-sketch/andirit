=== THE ISSUE ===
D-05 (ConcurrentMultiProcessAccess_FileLockingAndConsistency) is the only genuinely multi-process test in the S6.2 durability suite. The producer's implementation has a test logic defect: the writer process stages a unit but NEVER calls CompleteIndexRunAsync, so no publication is created. The test then expects readers to see a publication, which fails.

=== ROOT CAUSE ===
The test creates a writer that stages a unit but NEVER calls CompleteIndexRunAsync, so the run remains in "Running" state and is never published. The test then expects readers to see a publication, which fails because no publication exists.

### PRODUCER'S TEST LOGIC ERROR
The producer's test:
1. Creates a writer that stages a unit (Unit "unit:writer")
2. Does NOT call CompleteIndexRunAsync
3. Expects readers to see a publication
3. Asserts publication exists → FAILS (no publication was created)

The test logic assumes staging = publishing, but in LatticeDB, staging and publishing are separate operations. CompleteIndexRunAsync is what commits the staged unit and creates the publication.
